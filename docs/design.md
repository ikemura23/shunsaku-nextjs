# 設計書 - TED式 プレゼン指南所

**方針**: まずシンプルに。複雑な設計は一切不要。

## システム全体構成
```
ユーザー → フロントエンド(Next.js) → Gemini API → レビュー結果表示
```

## 基本構成
- **ファイル構成**: 
  - `src/pages/index.tsx` - メインページ（全機能を1ページに集約）
  - `src/pages/api/review.ts` - Gemini API呼び出し用のAPI Route
  - `src/styles/globals.css` - シンプルなスタイル
- **ライブラリ**: 
  - Next.js（フレームワーク）
  - Tailwind CSS（スタイリング）
  - @google/generative-ai（Gemini API）
- **データ**: セッション内で完結（永続化なし）

## UI設計
- **レイアウト**: 1カラムの縦長レイアウト
  1. ヘッダー（タイトル・説明）
  2. テキスト入力エリア（大きめのtextarea）
  3. レビュー実行ボタン
  4. 結果表示エリア（5つの観点別に表示）
- **スタイル**: 
  - 白背景、シンプルなカード形式
  - TED風の赤をアクセントカラーに使用
  - 読みやすいフォントサイズ
- **インタラクション**: 
  - ボタンクリック → ローディング表示 → 結果表示
  - エラー時はalertで通知

## 機能構成

### 1. テキスト入力機能
- 大きなtextareaでプレゼン内容を入力
- プレースホルダーで入力例を表示
- 文字数カウント表示（参考程度）

### 2. Gemini API連携
**API Route (`/api/review.ts`)**:
```typescript
// POST /api/review
// Body: { text: "プレゼン内容" }
// Response: { reviews: [...] }
```

**プロンプト設計**:
```
あなたはTEDトークの専門家です。以下のプレゼン内容を5つの観点で評価してください：
1. Emotion（感情を揺さぶる度）
2. Novelty（驚き・意外性）
3. Memorability（記憶に残る度）
4. Storytelling（ストーリー性）
5. Time（18分以内の構成）

各観点を1-10点で評価し、改善ポイントを具体的に提示してください。
```

### 3. 結果表示機能
- 5つの観点を別々のカードで表示
- 各カードに「スコア」「改善ポイント」を表示
- 全体的なコメントも表示

## データフロー
1. ユーザーがテキスト入力
2. 「レビュー実行」ボタンクリック
3. フロントエンドが `/api/review` にPOST
4. API RouteがGemini APIを呼び出し
5. レビュー結果をフロントエンドに返却
6. 結果を画面に表示

## 環境変数
- `GEMINI_API_KEY` - Gemini APIキー

## 開発のコツ
- **コピペでOK**: コードの美しさより動作優先
- **console.log多用**: デバッグ情報はたくさん出してOK
- **エラーハンドリング簡素**: try-catchは最小限、alertでエラー通知でもOK
- **状態管理不要**: useStateのみで十分
